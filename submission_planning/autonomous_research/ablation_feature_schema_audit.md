# Ablation Feature Schema Audit

Updated: 2026-06-18

Purpose: verify the current model-input feature layout before implementing ablation runs. This audit prevents ambiguous definitions of "w/o prior", "w/o focal difference", and "w/o glare cue".

## 1. Current Feature Source

The current synthetic feature tensor is generated by:

```text
src/simulate_antiglare_highres_samples.py::features_for_model()
```

Current code inspection indicates the feature tensor is:

```text
[stack frames, risk, dff, focus confidence, gadff, gadff confidence]
```

For a 17-layer focus stack, this gives 22 channels:

| Channel range | Meaning |
|---|---|
| 0-16 | raw focus-stack frames |
| 17 | mean glare / high-risk map |
| 18 | DFF depth prior |
| 19 | DFF focus confidence |
| 20 | GADFF depth prior |
| 21 | GADFF confidence |

## 2. Proposed Ablation Channel Masks

| Run ID | Variant | Channel handling |
|---|---|---|
| ABL-00 | Full S2R-FocusNet | keep all 22 channels |
| ABL-01 | Direct image-to-depth | keep stack frames, zero channels 17-21 |
| ABL-02 | w/o DFF/GADFF prior | keep stack and risk, zero channels 18-21 |
| ABL-03 | w/o focal difference | use upgraded 38-channel Focus-ResUNet features and zero channels 17-32 |
| ABL-04 | w/o glare cue | zero channel 17 and remove or recompute GADFF/risk-derived confidence only if code supports it |
| ABL-05 | w/o domain randomization | not a channel mask; requires dataset-generation control |
| ABL-06 | unbounded prediction | not a channel mask; requires model/loss or output-head control |

## 4. Interpretation

Passing this audit means the current feature tensor and proposed channel masks are documented. It does not mean the ablation variants have been trained. ABL-03 should use the upgraded Focus-ResUNet path audited in `abl03_focal_difference_implementation_audit.md`; ABL-05 and ABL-06 still require implementation decisions beyond simple channel masking.
